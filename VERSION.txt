DSH 一键装（官方 DeepSeek Harness web + 可选 kb-rag 知识库）  v1.1.1
生成时间：2026-09-16 19:49

⚠ 本文件是**开发者更新记录，不随发布包分发**（打包脚本 tools\make-release.ps1 会排除它，
  与它一起排除的还有脚本自己）。所以它里面的「维护者要求」「为什么这么改」这类内部说明
  不会流到终端用户手里。发布包里仍保留 sha256.txt 供用户核对文件完整性。

包含（= 发布包内容）：
  install.cmd            双击入口（安装 / 更新）
  GETTING-STARTED.txt    装之前看：这个包干什么、怎么用、出问题怎么办
  MODEL-SETUP.txt        装完看：第一次打开 DSH 要填 API Key，去哪申请、怎么填
  NEXT-STEPS.txt         装完之后四步：打开 / 接模型 / 选工作区 / 用知识库
  COMPAT.md              与 kb-rag 插件之间的依赖契约（维护者看）
  tools\install.ps1      安装逻辑
  tools\dsh-web.ps1      桌面快捷方式背后的启动器
  assets\                图标与许可证
  payload\               可选：放入 Node 压缩包，减少联网下载
  sha256.txt             各文件校验值（打包时重新生成）

它会做什么：
  1) Node.js   —— 有就用系统的；没有就下官方 zip 解压到用户目录（免管理员）
  2) dsh CLI   —— npm install -g @deepseek-ai/dsh + pnpm（官方 CLI，含 web 端）
  3) 快捷方式  —— 桌面「DeepSeek Harness」双击即启动 dsh web 并打开浏览器
  4) kb-rag    —— 可选（第 3 步问一句，回车＝装，回答 n ＝只装 DSH 本体）：
                  插件 + Python 引擎依赖 + 检索模型

设计要点：
  - 数据目录与官方一致：DSH_HOME = %USERPROFILE%\.dsh
  - 全部装在当前用户下，不需要管理员权限；不注册服务、不设开机自启
  - 下载多通道 + 校验：Node 用官方 SHASUMS256.txt 的 sha256；
    Python 安装包用 python.org 随包发布的 sha256（另有官方 MD5 兜底）
  - 插件按确切版本安装：@latest 会被 pnpm 的 minimumReleaseAge 策略降级，
    看起来装成功、实际版本没变（kb-rag 仓库 AGENTS.md 记录的坑）
  - 入口 URL 必须带 token；token 是进程级的、可复用，浏览器首次进入后服务端会
    种一个 30 天的 cookie（所以"裸访问 3080 一定 401"只对没进过的浏览器成立）
  - 可重复运行：已完成的步骤自动跳过，第二次运行即"更新"
  - 反复失败时：直接再双击一次往往就好（网络抖动 / 杀软误拦）

v1.1.1（本次发布）：
  * 等待期间显示进度动画：干等的地方会转圈（\ | / - 循环）+ 实时报「已等待 N 秒」。
    覆盖脚本里两处最长的无声等待：
      1) 静默安装 Python —— 原本 Start-Process -Wait 干等一两分钟，窗口一片死寂，
         新手以为卡死就关窗口，留下一半的 Python（比没装更难查）。改成轮询子进程 +
         转圈，退出码照常读得到。
      2) 装完后轮询等 dsh CLI / 插件就位（最长 20 秒）—— 原本这 20 秒完全无声。
      另外等 Python 出现的那一分钟（12×5 秒）也从"只印一句就沉默"改成全程转圈报秒数。
    两个实现要点写在代码注释里：转圈必须用 [Console]::Write 直接写控制台，不能走
    Write-Host —— Start-Transcript 会把主机输出全量记进日志，每秒八帧能把日志刷成
    几万行；输出被重定向 / 没有真控制台时自动不画动画，退化成纯文本。
    轮询间隔按检查代价给（读文件 250ms；Find-Python 要起进程，保持 5 秒一次）。
  * 结尾加一句引导：装成功时求个 Star，同时给出 Issues 入口；**安装失败时只给 Issues**
    （失败还推销很讨厌，但失败时用户更需要知道去哪问 —— 新手的默认行为往往是忍着用
    或者直接卸载，不会想到来提问）。地址由脚本顶部一个 $RepoUrl 常量派生
    （Issues = 该地址 + '/issues'），换仓库只改一行。
    当前指向 Breeze136/dsh-kb-rag：dsh-oneclick 尚未发布（npm 上 404、GitHub 上也没建仓），
    所以先指向这个包真正在装的那个项目（仓库与 Issues 均已核实存在）。等一键装独立建仓、
    发布之后改 $RepoUrl 这一行即可 —— 不指未经验证的地址，新手点开 404 比不引导还糟。
  * 失败路径再补三处（失败时这个 Issues 链接比成功时更值钱）：
      1) 日志路径直接写进失败提示里（"① 红色 [失败] 那几行 ② 这个日志文件"）——
         维护者最需要的就是它，而它单独一行放在最下面时，用户不知道那就是要贴的东西；
         成功路径不再重复打印它。
      2) 失败时**不再**提示"下载缓存可以整个删掉"，改成"先留着，重跑会直接用上"：
         装失败时缓存正是重跑最省事的东西（Node/Python 那几十 MB 不用重下），
         原来那句话会让人把它删掉。
      3) 失败时配色提亮（Gray + White），成功时保持压暗（DarkGray + Cyan）：
         小失败时压暗是对的（不抢报错优先级），但全失败时红字已经打完，
         最后这屏最有用的信息就是这个链接。
  * 精排模型那一问改成「讲清后果」，而不是硬劝：
      - 原来选 n 只回一句「好，跳过精排模型；以后想补下时重新双击本脚本即可」，没说代价。
      - 现在先说清跳过的两个后果：① 约 1.2GB（基础 95MB + 精排 1.1GB —— -NoModels 是两个
        都不预下载）要挪到第一次检索时才下：在会话里干等，网络受限还会失败；
        ② 精排用不上后，引擎不再判断「你库里到底有没有这个内容」（问库外问题不提示
        「无关」，只给一堆分数），排序质量也明显下降。
      - **没有**写成「不装就用不了插件」：那是假的。kb_engine.py 的检索路径对精排是
        try/except 降级（结果里附一句「精排不可用」后继续），插件照常能用。真话比吓唬
        更有说服力，也不会让用户跳过之后回来质疑文档。
      - 汇总表那行不再是含糊的「精排按用户选择」，改成明确三态：
        基础 + 精排模型均已缓存 / 基础 + 精排模型已下载 / 未预下载（首次检索时自动下约 1.2GB）。
      - GETTING-STARTED.txt 里那两个提问的说明同步改成同一口径。
  * install.ps1 全部面向用户的提示语统一改为书面语（115 条文案，含拼接片段）：
      - 去掉称呼与口癖（「你选了跳过」「别自己扛」「说一声就行」「照着做」「往往就好了」）、
        感叹号，以及当插入语滥用的破折号「——」（改成冒号或拆成两句）。
      - **保持不变的**是状态词（失败 / 跳过 / 已就绪 / 已安装 / 已创建 / 已最新 / 将 /
        将安装 / 将创建）—— 它们同时参与代码比较（`if ($State -eq '失败')`、汇总表配色
        的 `-match '已安装|已就绪|已创建|已最新'`），改文案会连带改坏逻辑；
        [信息]/[完成]/[注意]/[失败]/[跳过] 这些行首标签也照旧。
      - 改写方式可复核：对照表逐条精确替换（把引号一起匹配，避免误伤前缀相同的字符串），
        落盘后用「反向套回 + SHA-256 比对」验证 —— 反向还原后逐字节等于改写前，
        即改动严格限定在字面量内、没有代码被碰到。
      - 向导文档（GETTING-STARTED.txt / NEXT-STEPS.txt / MODEL-SETUP.txt）**不跟着改**：
        那是给纯新手看的教程，「别慌」「照着做」是有意为之的温度，与程序提示不是同一种文体。
      - 顺带修掉一个出厂就有的小毛病（维护者复核时发现）：收尾第 2) 条里
        `MODEL-SETUP.txt` 那一行原来**只打印一个裸路径、没有任何说明**，夹在编号步骤
        中间看不出那是什么；现在写成「详细文件在 <路径>」。
  * MODEL-SETUP.txt 第四节补一段「工作区该放在哪」（维护者要求）：
      - 原来只有一句「建议选你真正放文献的目录」，没给任何判断标准。

  * 预测并接住「不会解压的新手」（维护者要求，按发生频率×后果挑的）：
      - **最致命的一条：在压缩包里面直接双击 install.cmd**。Windows 会把 zip 当文件夹
        打开，但双击里面的文件并不会真的解压 —— tools\ 不在，脚本起不来，而原来的提示
        只有一句英文 "tools\install.ps1 not found"，中文新手直接卡死。
        现在 install.cmd 会判断两种情况（路径含 `.zip\` 或 Explorer 的 `Temp1_` 临时目录
        = 在压缩包里；否则 = 解压不完整），给出中文三步指引 + 他这次运行的位置。
        难点：install.cmd 必须保持纯 ASCII（cmd.exe 按 OEM 代码页解析，写中文会乱码），
        所以中文提示用 `-EncodedCommand`（UTF-16LE base64，与代码页无关）送进去 ——
        文件在磁盘上仍是纯 ASCII，已用字节级检查确认（非 ASCII 字节 = 0）。
      - 顺手把 install.cmd 从 `( ... )` 块改成 `goto` 标签：块内的 `%VAR%` 在块解析时就

        ③ 检测以管理员身份运行并提示（用错了会把东西装到管理员账户下，用户自己看不到）。
      - 新增 `$PackageVersion` 常量（VERSION.txt 不随包分发，所以版本号必须在脚本里也有一份），
        发版脚本会校验它与 VERSION.txt 首行一致，不一致**拒绝打包**。
      - GETTING-STARTED.txt 新增「第 0 步：先把压缩包解压出来」，并补两条高频困惑：
        窗口像卡住 = 点到了窗口进入「选择文本」状态（按回车恢复）、以及不要用管理员运行。

      - `$RepoUrl` 由 Breeze136/dsh-kb-rag 改为 **Breeze136/dsh-oneclick** —— 安装器结尾的
        「求 star」与「有问题去 issue」都跟着换。之前指向插件仓库只是权宜：安装器的报错
        （执行策略、pnpm、Python）会涌进插件的 issue 列表，两边维护线索混在一起。
      - 仓库侧就绪：仓库根 = 包目录，因此 VERSION.txt 与 tools\make-release.ps1 这两个
        「开发用、不随发布包分发」的文件正好待在仓库里；已提交首个 commit（18 个文件）。
      - 另加 `.gitattributes`（`* -text`）钉死行尾：本仓库靠 sha256.txt 校验用户拿到的文件，
        绝不能让 git 在 checkout 时改写行尾 —— 一次 LF/CRLF 转换就让所有校验值对不上，
        而用户看到的现象是"下载的文件被人动过"。已用 `git restore .` 往返实测：逐字节无损。
      - `.gitignore` 排除 发布\、payload 压缩包、日志与编辑器产物；这两个 git 配置文件

v1.1.0（本次发布）：
  * 知识库插件改成可选：第 3 步问「要不要装 kb-rag」，回车＝装（默认），
    回答 n ＝只装官方 DSH web，第 4 步的 Python/引擎/模型一起跳过并在汇总表标注。
  * 启动器（桌面图标）重写，专治「第一次能开、之后再双击就卡住」：旧版在端口被占、
    又拿不到入口链接时，会红字报错并停在「Press Enter to close」等回车 —— 用户看到的
    就是窗口卡死。现在依次尝试 上次存的链接 → 服务日志里的链接；两个都拿不到时，
    改用一个空闲端口自己起一个（dsh web --port 0），保证图标永远能开。
    另外：窗口里会打印**完整**的带 token 网址（旧版把 token 去掉，浏览器没自动开时
    用户手里什么都没有）；浏览器优先交给 dsh 自己开，日志显示它开失败时我们再兜底；
    启动期间每 10 秒报一次进度（最长 180 秒，旧版 120 秒一声不吭）；PATH 里补上
    node 自己的目录；复制启动器/图标时 Unblock-File。
  * Python 探测补齐：加注册表（HKCU/HKLM，官方安装器默认不往 PATH 写）和
    C:\Program Files\Python3xx（「为所有用户安装」的默认位置）；商店版 python3 别名放最后试。
  * 装完不再只验证一次：Python 安装后轮询最多 60 秒，dsh CLI / 插件装完后轮询最多 20 秒
    —— 杀软实时扫描会让刚写好的文件短暂读不到，这是「第一次报错、第二次就好」的一大来源。
  * npm / pnpm 失败自动换下一个源重试一次（下载和 pip 早就有重试，只有这两步没有）。

v1.0.0 修复记录：
    1) 便携版 Node.js 装不上的真正原因：解压后要把目录搬到 %LOCALAPPDATA%\DSH\node，
       而父目录 %LOCALAPPDATA%\DSH 那会儿还不存在（它是第 5 步建快捷方式时才建的），
       Move-Item 于是报「未能找到路径中的某个部分」；又因为那是非终止错误，外层 catch
       抓不到，脚本还会先打一句「[完成] Node.js 已就位」，日志看着自相矛盾。
       现在：先建父目录 → Move-Item 加 -ErrorAction Stop → 移动后校验 node.exe 真的到位。
    2) 演练模式 -DryRun 在干净机器上不再把「将会安装」报成失败（不再满屏红字 + 退出码 1）。

       MD5 取自官方下载页；「文件存在即通过」这条老规矩不再适用于它。
    4) 找不到引擎安装脚本时，明确说明真实原因是「第 3 步插件没装上」。
